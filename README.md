# NAPI EEPROM MAC assignment v12.3

Назначает сетевым интерфейсам платы NAPI (RK3308) постоянные MAC-адреса из
EEPROM вместо случайных, которые выдают драйверы (`smsc95xx`, `w5100`).

## Имена интерфейсов

`99-napi-net-names.rules` даёт постоянные имена по `ID_PATH` (контроллер +
порт), без номера USB-шины:

| Имя | Контроллер, порт | Секция `mac.conf` |
| --- | --- | --- |
| `lanusb1` | `ff400000.usb` (DWC2 OTG), 1.1 | `usb_eth_3` |
| `lanusb2` | `ff400000.usb` (DWC2 OTG), 1.2 | `usb_eth_4` |
| `lanusb3` | `ff440000.usb` (EHCI), 1.1 | `usb_eth_1` |
| `lanusb4` | `ff440000.usb` (EHCI), 1.2 | `usb_eth_2` |
| `lanw5500` | `ff140000.spi`, CS0 (SPI2) | `w5500_spi2` |

Назначение MAC от имён не зависит. Файл заменяет одноимённое правило Armbian:
`install.sh` сохраняет его в `/etc/napi/99-napi-net-names.rules.orig`,
`uninstall.sh` возвращает. Оба скрипта вызывают `update-initramfs -u`, потому
что Debian/Armbian копируют `/etc/udev/rules.d` в initramfs.

## История

v12.3 относительно v12.2 (то же, что v13.1 в ветке `c-port`):

* `99-napi-net-names.rules`: имена по `ID_PATH` вместо номера шины
  (`KERNELS=="2-1.1:1.0"` в правиле Armbian); номер шины EHCI зависит от
  порядка инициализации контроллеров, при шине 3 адаптеры оставались
  `eth2`/`eth3`;
* `install.sh`/`uninstall.sh`: сохранение и возврат правила Armbian,
  `update-initramfs -u`; в `75-napi-mac.rules` — `TEST==`, чтобы в initramfs,
  где программы нет, правила ничего не запускали.

v12.2 относительно v12.1 (проверка на плате NAPI-C с Napi Linux 0.3.2, Yocto):

* третье udev-правило: `bind` драйвера `smsc95xx` к USB-интерфейсу запускает
  `napi-set-mac --all`. В образе Yocto два адаптера на разных контроллерах
  получают одно предсказуемое имя (`enu1u1`), udev отбрасывает событие `add`
  проигравшего целиком, и если `smsc95xx` загрузился позже `at24` и сервиса,
  MAC этого адаптера никто не ставил (видно на одной из перезагрузок).
  Событие `bind` приходит после регистрации интерфейса и от имени не зависит.

Проверено: три перезагрузки подряд, все MAC верные, хотя имена интерфейсов
между загрузками менялись.

v12.1 относительно v12 (проверка на плате NAPI-C, Armbian 26.8, ядро 6.18):

* udev передаёт `napi-set-mac --ifindex $env{IFINDEX}`, имя определяется при
  запуске. `$name` и `$env{INTERFACE}` подставляются при разборе правила 75,
  до `NAME=` из `99-napi-net-names.rules`, поэтому при повторной энумерации USB
  скрипт получал старое имя `eth0`, ничего не находил и оставлял случайный MAC.
  Ошибка была и в v11; при загрузке не проявлялась, потому что интерфейсы
  переименовывает ещё initramfs;
* под udev коды 3 и 4 возвращаются как 0, чтобы udev не писал
  «failed with exit code 3» на каждый неуправляемый интерфейс.

Проверено на плате: `--check`, проход сервиса, `udevadm trigger`,
unbind/bind USB-адаптеров на обоих контроллерах, отвязка `at24`
(интерфейс отложен, MAC выставлен при привязке EEPROM), перезагрузка.

v12 относительно v11:

* EEPROM, появившаяся позже интерфейсов (`at24` модулем), больше не оставляет
  случайные MAC: udev-правило на `bind` драйвера `at24` к `1-0050` запускает
  проход `napi-set-mac --all`; интерфейс без EEPROM получает код 4 «отложено»,
  а не ошибку;
* `napi-set-mac --all` выполняет проход в одном процессе (`napi-set-macs` —
  обёртка), `--check` проверяет конфиг и EEPROM и показывает план, ничего не меняя;
* конфиг проверяется целиком: уникальность *итоговых* слотов (с умолчаниями
  W5500 и слотом 1 при `set_native_eth_mac`), диапазон 1..8, обязательные ключи
  с именем секции, пересечение USB-секций, неизвестные секции (`--check`),
  отсутствие файла пишется в лог;
* `controller` может содержать несколько контроллеров (EHCI + OHCI-компаньон);
* MAC отклоняется, если дублирует другой действительный слот; неинициализированная
  EEPROM (все `00`/`FF`) диагностируется отдельно;
* если интерфейс не удалось поднять обратно, лог сообщает, что он остался DOWN;
* `ip(8)` ищется в `/usr/sbin`, `/sbin`, `/usr/bin`, `/bin`;
* `install.sh` проверяет наличие `python3`;
* юнит-тесты `tests/` на контрольном образе п. 11 и поддельном sysfs.

v11 относительно v10:

* `napi-set-mac` сверен с `NAPI_EEPROM_SPEC.md`: проверка `platform_id`,
  `mac_count <= 8`, CRC до чтения полей; тест на контрольном образе п. 11;
* добавлен `uninstall.sh`;
* спецификация включена в проект.

v10 относительно v9:

Основной механизм: udev-правило `75-napi-mac.rules`, запускающее
`napi-set-mac` на каждое событие `add` физического сетевого интерфейса.
Это закрывает:

* гонку с энумерацией USB при загрузке (`udev-settle` убран);
* повторную энумерацию USB после reset, когда `smsc95xx` выдаёт новый случайный MAC;
* hotplug.

`napi-mac.service` остаётся как страховочный проход и как способ применить
изменённый конфиг без перезагрузки.

Исправления в `napi-set-mac`:

* из EEPROM читаются только 126 байт, а не весь чип;
* USB-порт сравнивается только с собственным каталогом устройства (`1-1.1`),
  адаптер за внешним хабом на этом порту больше не подхватывается;
* проверка уникальности `mac_slot` среди включённых секций;
* логирование в syslog под udev, коды выхода 0 / 3 / 1.

`install.sh` не перезаписывает существующий `mac.conf`.

## Формат EEPROM

Раскладка v3 по `NAPI_EEPROM_SPEC.md` (редакция 2026-09-24). Скрипт использует
только `magic`, `format_version`, `platform_id`, `mac_count`, `mac[0..7]` и
`crc32`; остальные поля не читаются. Проверяется на контрольном образе из п. 11
спецификации (CRC `0xE53A0E41`, MAC1 `02:9e:e6:97:4d:60`).

## Коды выхода `napi-set-mac`

| Код | Значение |
| ---: | --- |
| 0 | MAC выставлен или уже верный (`--all`/`--check`: без ошибок) |
| 1 | ошибка: EEPROM, конфиг, `ip(8)` |
| 3 | интерфейс не описан в конфиге |
| 4 | интерфейс описан, но EEPROM ещё нет; обработает проход при её появлении |

## Тест на плате

```sh
./install.sh
/usr/lib/udev/napi-set-mac --check
udevadm trigger --subsystem-match=net --action=add
journalctl -t napi-set-mac --no-pager
ip -br link
reboot
journalctl -b -t napi-set-mac -u napi-mac.service --no-pager
```

Ожидаемое после перезагрузки: строки `napi-set-mac[..]: ethN: usb_eth_M MACK xx:xx:.. OK`
от udev и `... ALREADY` от сервиса.

Проверка USB re-enumeration:

```sh
echo 1-1.1 > /sys/bus/usb/drivers/usb/unbind
echo 1-1.1 > /sys/bus/usb/drivers/usb/bind
journalctl -t napi-set-mac -n 3
```

## Удаление

```sh
./uninstall.sh          # конфиг /etc/napi сохраняется
./uninstall.sh --purge  # вместе с конфигом
```

Уже назначенные MAC остаются на интерфейсах до перезагрузки.
